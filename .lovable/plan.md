# خطة: تجميد حقول التقرير + سير عمل الموافقة على التغيير

## الفكرة
بعض الحقول (مثل: عدد الكوادر الثابتة، سعة الموقع، أطوال الطرق…) تُدخَل مرة واحدة وتبقى ثابتة عبر التقارير اليومية. بعد أول إدخال يصبح الحقل «مجمّداً» ويظهر للقارئ فقط. أي تعديل يتطلب طلب موافقة يوقّع عليه **المشرف** ثم **المدير العام** معاً.

## تدفّق المستخدم
1. في «إدارة حقول التقرير»: خانة اختيار جديدة عند تعريف/تعديل أي حقل: **«تجميد بعد أول إدخال (تعديله يتطلب موافقة)»**.
2. في نموذج التقرير اليومي:
   - إذا كان الحقل مجمّداً وله قيمة سابقة لنفس المكتب → يُعرض للقراءة فقط مع أيقونة قفل، وتُنسخ القيمة تلقائياً إلى التقرير الجديد.
   - يظهر زر «طلب تعديل» بجانب الحقل → يفتح نافذة يُدخل فيها المستخدم القيمة الجديدة + السبب.
3. صفحة جديدة **«طلبات تعديل الحقول المجمّدة»** (تظهر للمشرف والمدير العام):
   - المشرف يوافق أولاً → الحالة تصبح «بانتظار المدير العام».
   - المدير العام يوافق ثانياً → تُطبَّق القيمة الجديدة على أحدث تقرير للمكتب ويتم إعلام مقدّم الطلب.
   - أيّ منهما يستطيع الرفض مع سبب.

## التغييرات التقنية

### قاعدة البيانات
- `report_field_definitions`: إضافة عمود `is_frozen boolean not null default false`.
- جدول جديد `frozen_field_change_requests`:
  ```
  id, office_id, field_key, current_value(jsonb),
  requested_value(jsonb), reason, requested_by,
  supervisor_approved_by, supervisor_approved_at,
  director_approved_by, director_approved_at,
  rejected_by, rejected_at, rejection_reason,
  status: 'pending_supervisor' | 'pending_director' | 'approved' | 'rejected',
  applied_at, created_at
  ```
- GRANTs + سياسات RLS:
  - المُدخِل يقرأ/ينشئ طلباته فقط (ضمن مكتبه).
  - المشرف يرى طلبات مكاتبه المسموح بها ويوافق/يرفض في مرحلة `pending_supervisor`.
  - المدير العام يرى الكل ويوافق/يرفض في مرحلة `pending_director`.

### الواجهة الأمامية
- `ReportFieldDefinition` type + `FieldDefinitionsManager.tsx`: خانة «تجميد الحقل» + وسم أخضر «مجمّد» بجانب الحقل.
- `ReportPage.tsx` / `FormField.tsx`: قفل الحقول المجمّدة التي لها قيمة سابقة، إظهار أيقونة قفل + زر «طلب تعديل».
- مكوّن `FrozenFieldChangeDialog` لإرسال الطلب.
- صفحة `FrozenRequestsPage.tsx` مع تبويبات (بانتظاري / تمت / مرفوضة) وإضافتها إلى قائمة التنقّل للمشرف والمدير.
- عرض إشعار (toast + جرس الإشعارات) لمقدّم الطلب عند الموافقة/الرفض.

### الباك-إند / الـ API
- توسيع `src/lib/api.ts` بدوال: `createFrozenChangeRequest`, `listFrozenChangeRequests`, `approveFrozenChangeRequest`, `rejectFrozenChangeRequest`.
- عند تقديم تقرير جديد: إن كان الحقل مجمّداً، تُستبدَل القيمة المرسلة بالقيمة المخزّنة سابقاً لضمان عدم الالتفاف على القفل.

## ملاحظات
- الحقول الحالية تبقى كما هي؛ الميزة معطّلة افتراضياً.
- الميزة تنطبق على الحقول الرقمية والنصية والاختيارية؛ الحقول من نوع «موقع/مسار» ستُدعم لاحقاً إن احتاج المستخدم.
- الاحتساب في الإحصائيات لا يتأثر (تُستخدم القيمة الحالية دائماً).
